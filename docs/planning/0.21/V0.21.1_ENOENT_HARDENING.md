# v0.21.1 — Store Empty-State Hardening

## Origin

A full north-star roadmap audit (`dev/AUTOFORGE_NORTH_STAR_REVISED_POST_V0.14_TO_V0.25.md`)
against live CLI behavior found that several project-scoped stores threw raw,
uncaught `ENOENT` errors — stack traces with no exit-code contract — when a
domain had never been initialized. This never surfaced in the test suite
because every existing test wrote an artifact before reading it; the defect
only reproduced by running the CLI cold against a fresh or self-hosted
project, which is exactly what surfaced it here.

`src/twin/store.ts` already handled this correctly: `read()` catches `ENOENT`
and resolves `null`, and `commands/twin.ts` turns that into a friendly
stderr message and `EXIT_CODE.invalidState`. That pattern is now the
project-wide contract for every single-file project-scoped store.

## Fixed

- `src/governance/store.ts` (`ConstitutionStore.load()`) — now resolves
  `null` instead of throwing when `constitution.json` does not exist.
- `src/domain/store.ts` (`DomainStore.load()`) — now resolves `null` instead
  of throwing when `domain.json` does not exist.
- `src/planning/store.ts` (`PlanningArtifactStore.read()`) — now resolves
  `null` instead of throwing when a planning artifact kind has not been
  generated; `isFresh()` returns `false` for a missing artifact instead of
  rejecting.

## Command-level behavior change

| Command                                    | Before                                                                   | After                                                                                             |
| ------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `autoforge constitution list\|show\|check` | uncaught `ENOENT` stack trace                                            | `No project constitution found. Run \`constitution init\` first.` (exit 4)                        |
| `autoforge domain list\|show\|check`       | uncaught `ENOENT` stack trace                                            | `No domain artifact found. Run \`domain init\` first.` (exit 4)                                   |
| `autoforge planning show <kind>`           | uncaught `ENOENT` stack trace                                            | ``No <kind> planning artifact found. Run `intent assess` with --artifact <kind> first.`` (exit 4) |
| `autoforge planning handoff <kind> ...`    | generic `Error: ENOENT...` (exit 3, `notFound`) via `reportCommandError` | same message as above (exit 4, `invalidState`) — now consistent with `show`                       |
| `autoforge planning list`                  | already tolerant (per-kind `try/catch`)                                  | unchanged behavior, simplified to a `null` check                                                  |

All four now use `EXIT_CODE.invalidState` (4) consistently, matching the
existing `twin` convention, rather than mixing `unexpected` (1) or
`notFound` (3) depending on which code path happened to catch the error.

## Contract note for callers

`ConstitutionStore.load()`, `DomainStore.load()`, and
`PlanningArtifactStore.read()` / `.isFresh()` are no longer guaranteed to
resolve a value — **any new caller must null-check the result** before use.
`src/orchestration/context.ts` already worked around the old throwing
behavior with an ad hoc `.catch()`; that workaround was removed since the
store now handles it natively.
