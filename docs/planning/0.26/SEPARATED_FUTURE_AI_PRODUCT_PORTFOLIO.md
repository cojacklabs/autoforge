# Separated Future AI Product Portfolio

Status: Preserved product concepts; outside AutoForge implementation scope
Established: 2026-08-30
Product name: Undecided

## Purpose

This document preserves ideas previously assigned to AutoForge that now belong
to a separate future CoJack Labs AI. Nothing here authorizes implementation in
the AutoForge repository.

## Future AI Responsibilities

The separately named AI may eventually own:

- general conversation, reasoning, and user-level memory;
- model selection, provider routing, effort controls, credentials, and usage;
- cross-application work such as email, messaging, support, and research;
- personal and organizational assistant experiences;
- a first-party interactive CLI, TUI, Web application, and other channels;
- subscriptions, hosted execution, cloud synchronization, and accounts;
- multimodal understanding and a visual prompt-to-product workspace.

## Visual Product Studio

The preserved destination is a unified product-engineering workspace where
conversation, a visual canvas, and raw code are equal first-class editing
modes. It may guide a project from a flagship prototype through design,
architecture, frontend and backend implementation, data, identity, security,
testing, deployment, observability, documentation, incident readiness, and
long-term support.

The future AI may integrate with Framer, Figma, Stitch, TypeUI, and similar
tools. When a technical project is governed by AutoForge, the visual product
must consume versioned framework artifacts and return proposals, diffs, and
evidence through supported contracts rather than create competing truth.

## Relationship Contract

```text
Future CoJack Labs AI
  Conversation + personal memory + models + product experiences
                         |
                         v
                 AutoForge interfaces
  Project knowledge + context + governance + orchestration + validation
                         |
                         v
             Replaceable specialist agents and tools
```

The future AI is one possible AutoForge client. AutoForge remains usable
without it, and the AI may perform non-technical work without AutoForge.

## Transfer Rules

Before any concept moves into the future AI repository:

1. assign it a new product-owned work item;
2. identify which project contracts remain owned by AutoForge;
3. avoid copying canonical framework state into a separate memory system;
4. define permissions, retention, provider, and security boundaries;
5. preserve source decisions and provenance;
6. independently validate naming, licensing, package, and domain availability.

The names AutoForge, Forger, `autoforge.sh`, and `autoforgerai.com` are not
automatically assigned to the future AI.
